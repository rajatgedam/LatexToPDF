Pick your way to run it

Download and double-click

One zip per OS (macOS Apple Silicon and Intel, Linux x64 and arm64, Windows x64). Unzip, open LatexToPDF.command, LatexToPDF.sh or LatexToPDF.bat. No installs.

Verify with the SHA256SUMS.txt on the release. Builds are unsigned, so macOS and Windows may show a first-run warning.

Docker (any OS)

docker run --rm -p 127.0.0.1:5757:5757 \
  ghcr.io/rajatgedam/latextopdf

Then open http://127.0.0.1:5757. Runs as non-root; add --read-only --tmpfs /tmp --cap-drop ALL to lock it down further.

For AI agents and scripts

latex2pdf -i resume.tex -o resume.pdf --json

One JSON result, stable exit codes, also a Node API and an HTTP API. See the README.

Why there is no "convert online" button here

GitHub Pages can only host static files, and running other people's LaTeX on a public server is a real security risk (LaTeX can read files and run programs unless it is locked down). It also means your resume would travel to someone else's computer. So the converter runs locally, where your files stay yours. This page is just the front door.

Security in one paragraph

Loopback-only server, Host and Origin checks, strict CSP, rate limits and size caps; each compile runs in an isolated temp folder with a timeout, a scrubbed environment, a static policy scan and, on macOS, an OS sandbox. The engine download is pinned by SHA-256 and the backend has zero runtime npm dependencies. Release files carry build provenance attestations. Details are in the repository's security rules.
