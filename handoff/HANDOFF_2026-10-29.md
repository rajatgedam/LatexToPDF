## What changed this session
LatexToPDF became **ToolMaster**, a modular system of independent tools:
- Repo renamed on GitHub to `rajatgedam/ToolMaster` (public; old URLs redirect), local folder `RGit/ToolMaster`, npm package `toolmaster`, env prefix `TOOLMASTER_*`, binary `toolmaster`, Docker images `ghcr.io/rajatgedam/toolmaster[-<tool>]`.
- New layout: `core/` (kernel), `tools/<id>/` (one folder per tool), `web/` (generic UI), `scripts/`, `test/helpers/`. See ARCHITECTURE.md for the module map and the tool contract.
- New tool **LaTeX to DOCX** (`latex-to-docx`, Pandoc 3.13 with `--sandbox`, HTML preview).
- Start menus: web (search, categories, cards, keys) and terminal (`toolmaster` with no args).
- Per-tool distribution: `--tools` bundles, per-tool Docker images, `TOOLMASTER_TOOLS` runtime filter.
- Breaking API renames (no users yet): `COMPILE_FAILED` -> `TOOL_FAILED`, `POST /api/compile` -> `POST /api/tools/:id/run`, `LATEX2PDF_*` -> `TOOLMASTER_*`, `X-Latex2pdf-*` -> `X-ToolMaster-*`, `latex2pdf` CLI -> `toolmaster <tool>`, cache `vendor/tectonic-cache` -> `vendor/cache/tectonic`.

## State at end of session
Working and tested on macOS arm64: core, both tools, CLI + terminal menu, secure HTTP server, web app, portable bundles (all / one tool), sandbox. CI covers Linux; release workflow builds 5 OS targets x 3 bundles. Repo: https://github.com/rajatgedam/ToolMaster (public), branch `main`.

Quick use:
```
npm run setup                                  # engines + web deps + web build (first time)
node bin/toolmaster.mjs                        # interactive menu
node bin/toolmaster.mjs latex-to-docx -i cv.tex -o cv.docx --json
npm start                                      # web app at http://127.0.0.1:5757
npm test                                       # unit + integration + web
npm run package -- --tools latex-to-docx --zip # one-tool portable bundle in dist/
```

## Gotchas
- Do not use `brew install tectonic` or `brew install pandoc` (they pull many dependencies and upgrade shared libraries); `toolmaster install` is the supported path.
- Terminal summaries can corrupt long hashes: write digests to a file and read them back.
- Node test runner runs files in parallel: keep temp dirs private per test file; real-engine tests are skipped when the engine is missing, and run with `--test-concurrency=1`.
- `node:readline` returns `null` at EOF; always handle it in prompts (an `undefined` slipped through once and looped forever).
- Pandoc output in DOCX tests: use plain strings in `new Response(...)` under jsdom (a jsdom Blob stringifies to `[object Blob]`).
- The user's own resume files live outside the repo (`RGit/VKProfile`); never commit them. They are useful for manual checks of both tools.
